Facilitator-managed custody: `voucherStoreMode`, `extra.voucherManager` (`"facilitator"` on a managed 402; `["server", "facilitator"]` on `/supported`), a boolean `extra.delegatedRefund` on `/supported` (always emitted; `true` iff the facilitator configures `resolveCallerIdentity`; an absent field means a legacy facilitator), managed refund consent (caller identity when the 402 omits `refundAuthorizer`, otherwise a `refundAuthorizerSignature` from the server's own refund signer; the facilitator then re-signs), `pendingId`/`cancel`, `chargeCount` (attested onchain per claim in the ERC-8021 `m.x402ChargeCounts` metadata, which needs no builder code, and read back with `decodeClaimAttestation`, which joins rows to `Claimed` events by `channelId`), and `@x402/evm/batch-settlement` plus facilitator file/redis storage exports. Managed `/settle` lock-store I/O now degrades to optimistic (matching `inspectAdmission` and Go) instead of throwing after the resource handler. Deposit settle swallows a throwing `resolveCallerIdentity` so the charge is still persisted. `readExtraNumber("0")` is no longer treated as missing. In-memory `get`/`list`/`updateChannel` clone records so in-place mutation does not persist.
